# Data Storage & Spatial Indexing Specification

This document details the relational domain models, PostGIS geospatial storage design, and spatial database indexing strategies for **SeismoAtlas**.

---

## 1. Primary Database Selection

SeismoAtlas utilizes **PostgreSQL** paired with the **PostGIS** geospatial extension as its primary data store. PostGIS provides standard spatial data types (Point, LineString, Polygon), spatial indexing (GiST/SP-GiST), and fast spatial operations (`ST_DWithin`, `ST_Contains`, `ST_Intersects`) essential for real-time spatial querying.

## 3. Entity Schema Specifications

### 3.1 `Earthquake` Model

The central entity for cataloged seismic events.

```sql
CREATE TABLE earthquakes (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    external_id VARCHAR(255) UNIQUE NOT NULL,
    origin_time TIMESTAMPTZ NOT NULL,
    latitude NUMERIC(9,6) NOT NULL,
    longitude NUMERIC(9,6) NOT NULL,
    depth_km NUMERIC(6,2) NOT NULL,
    magnitude NUMERIC(3,1) NOT NULL,
    magnitude_type VARCHAR(10) NOT NULL,
    location_name VARCHAR(255),
    region VARCHAR(255),
    event_type VARCHAR(50) DEFAULT 'earthquake',
    source VARCHAR(100) NOT NULL,
    catalog_version VARCHAR(50) NOT NULL,
    geom GEOMETRY(Point, 4326) NOT NULL,
    created_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP
);
```

### 3.2 `HazardCalculation` Model

Tracks scientific hazard calculations generated by the OpenQuake engine or authoritative models.

```sql
CREATE TABLE hazard_calculations (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    location_id UUID REFERENCES locations(id),
    model_id UUID REFERENCES hazard_models(id),
    model_version VARCHAR(50) NOT NULL,
    calculation_type VARCHAR(50) NOT NULL, -- e.g., 'classical_psha', 'scenario'
    imt VARCHAR(20) NOT NULL,              -- Intensity Measure Type: PGA, SA(0.2s), SA(1.0s)
    return_period INTEGER NOT NULL,        -- e.g., 475, 2475 years
    time_window_years INTEGER NOT NULL,    -- e.g., 50 years
    probability_of_exceedance NUMERIC(5,4),-- e.g., 0.1000 (10%)
    result_uri VARCHAR(512),               -- Path to detailed Cloudflare R2 artifact
    config_hash VARCHAR(64) NOT NULL,      -- Hash for auditability
    created_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP
);
```

## 4. Spatial & Attribute Indexing Strategy

High-performance geospatial and temporal filtering depends on multi-column and spatial indexing.

```text
Earthquake Table Indexing Structure:
 ├── origin_time                (B-Tree)  --> Time range filtering
 ├── magnitude                  (B-Tree)  --> Magnitude threshold filtering
 ├── depth_km                   (B-Tree)  --> Depth filtering
 ├── source                     (B-Tree)  --> Provider/Catalog filtering
 └── geom                       (GiST)    --> Spatial bounding box & proximity queries

Location / Region Indexing:
 └── geom                       (GiST)    --> Spatial intersection

Fault & Seismic Source Indexing:
 └── geom                       (GiST)    --> Spatial bounding box & proximity queries
```

### Index DDL Statements

```sql
-- Spatial GiST Index for Earthquakes
CREATE INDEX idx_earthquakes_geom ON earthquakes USING GIST (geom);

-- B-Tree Indexes for Frequent Filter Attributes
CREATE INDEX idx_earthquakes_origin_time ON earthquakes (origin_time DESC);
CREATE INDEX idx_earthquakes_magnitude ON earthquakes (magnitude DESC);
CREATE INDEX idx_earthquakes_depth ON earthquakes (depth_km);
CREATE INDEX idx_earthquakes_source ON earthquakes (source);

-- Composite Index for Common Map Bounding Box + Time + Magnitude Queries
CREATE INDEX idx_earthquakes_spatial_filter 
ON earthquakes USING GIST (geom) 
INCLUDE (magnitude, origin_time);
```
